# Ритм — таск-трекер команды

Задачи на день, неделю и месяц, задачи от руководителя одному человеку или всей команде, учёт времени в один клик и итоги недели. Вход по персональной ссылке и паролю, без почты.

Запуск занимает около 30–40 минут, программировать не нужно: вы просто копируете файлы в нужные места.

> В этом репозитории сайт лежит в корне (`index.html`, `css/`, `js/`) и публикуется через GitHub Pages: Settings → Pages → Deploy from a branch → `main` / `(root)`. Адрес подключения к базе — в файле `js/config.js`. Папка `supabase/` — база и серверная функция для Supabase.

## Что внутри

- `web/` — само приложение (сайт). Его нужно разместить в интернете.
- `supabase/schema.sql` — база данных и права доступа. Вставляется в Supabase.
- `supabase/functions/tracker-api/index.ts` — серверная функция: вход по ссылкам, участники, демоданные.
- `test/` — проверки для разработчика, для запуска не нужны.

## Шаг 0. Проверьте доступ

Откройте https://supabase.com с рабочего компьютера и с телефона без VPN. Если сайт не открывается, трекер у коллег работать не будет. Тогда лучше показать эту папку ИТ-отделу: ту же базу можно развернуть на своём сервере компании (Supabase бывает и в самостоятельной установке).

Перед тем как хранить рабочие задачи во внешнем сервисе, стоит согласовать это с ИТ или службой безопасности.

## Шаг 1. Создайте проект Supabase

1. Зарегистрируйтесь на https://supabase.com. Бесплатного тарифа для команды до 30 человек хватает.
2. Нажмите **New project**. Введите название (например, `ritm`), придумайте пароль базы и сохраните его. Регион выберите ближайший, например Frankfurt (Central EU).
3. Подождите пару минут, пока проект создаётся.

## Шаг 2. Создайте базу

1. В левом меню откройте **SQL Editor**, затем **New query**.
2. Откройте файл `supabase/schema.sql` в любом текстовом редакторе, скопируйте весь текст и вставьте его в окно запроса.
3. Нажмите **Run**. Должно появиться «Success». Сообщение про pg_cron — это нормально.

## Шаг 3. Разместите серверную функцию

1. В левом меню откройте **Edge Functions** → **Deploy a new function** → **Via Editor**.
2. Назовите функцию строго `tracker-api`.
3. Удалите пример кода, вставьте весь текст из `supabase/functions/tracker-api/index.ts` и нажмите **Deploy**.
4. Откройте настройки функции (**Details** или **Settings**) и **выключите** проверку JWT: «Enforce JWT verification» или «Verify JWT». Сохраните. Без этого вход по ссылке работать не будет.
5. В **Edge Functions** → **Secrets** добавьте секрет:
   - Name: `SETUP_SECRET`
   - Value: любой придуманный код, например `ritm-2026-start`. Он понадобится один раз, при создании команды.

## Шаг 4. Впишите адрес проекта в приложение

1. В Supabase откройте **Project Settings** → **API** (или **API Keys**).
2. Скопируйте **Project URL** и публичный ключ: **anon public** или **Publishable key**. Секретный ключ (service_role или Secret) сюда не вставляйте.
3. Откройте файл `js/config.js` (в архиве — `web/js/config.js`) и замените `ВАШ_PROJECT_URL` и `ВАШ_ANON_KEY` на скопированные значения, оставив кавычки.

## Шаг 5. Разместите сайт

Самый простой способ — Netlify Drop:

1. Откройте https://app.netlify.com/drop и войдите (можно через почту или GitHub).
2. Перетащите папку `web` целиком в окно браузера.
3. Через несколько секунд появится адрес вида `https://что-то.netlify.app`. Это адрес вашего трекера. В настройках сайта его можно переименовать, например в `ritm-hr.netlify.app`.

Подойдёт любой хостинг статических сайтов: Vercel, GitHub Pages, сервер компании. Нужно просто выложить содержимое папки `web`.

Если позже поменяете `config.js` или файлы приложения, перетащите папку `web` ещё раз в раздел **Deploys** того же сайта.

## Шаг 6. Первый вход

1. Откройте адрес трекера. Появится форма «Создайте команду».
2. Введите код из `SETUP_SECRET`, название команды, своё имя и придумайте пароль.
3. Трекер покажет **вашу персональную ссылку**. Сохраните её в закладки или заметки: для входа с телефона и других компьютеров понадобятся ссылка и пароль.
4. Чтобы посмотреть, как выглядит заполненный трекер, откройте **Команда** → **Заполнить демоданными**. Потом нажмите там же **Очистить демоданные**. Если отделов ещё не было, демо добавит 4 примера отделов — после очистки они останутся, их можно переименовать или удалить.

## Шаг 7. Добавьте коллег

**Команда** → **Добавить участника**: имя, должность и роль. Трекер покажет ссылку для этого человека. Отправьте её лично, в мессенджере. Человек откроет её, придумает пароль и окажется в трекере.

Как устроен вход:
- Вход = персональная ссылка + пароль. На устройстве, где ссылку уже открывали, достаточно пароля.
- Раз в 14 дней трекер снова спрашивает пароль.
- Забыли пароль — администратор нажимает **Новая ссылка / сброс пароля**. Старые ссылка и пароль перестают работать, по новой ссылке человек задаёт новый пароль.
- Сменить пароль можно в **Настройках**.

- Роли:
  - **Руководитель** видит личные задачи и итоги всех сотрудников и управляет командой.
  - **Администратор** управляет командой (люди, ссылки, роли, колонки, категории), но видит только свои и командные задачи.
  - **Участник** видит свои и командные задачи. Командную задачу может поставить любому коллеге или всем.
- Отделы у каждого свои: любой участник добавляет нужные ему отделы (раздел «Команда» → «Мои отделы» или кнопка «Новый отдел» на доске). Чужие отделы видит только руководитель.
- Остальным — **Участник**: свои задачи и командные, личные задачи коллег не видны.
- Если ссылка попала не туда, нажмите **Новая ссылка / сброс пароля**: старая сразу перестанет работать.
- **Отозвать доступ** выключает человека на всех устройствах, его задачи сохраняются.

## Обновление уже запущенного трекера

Если база была создана по старой версии `schema.sql`:

1. Supabase → SQL Editor → New query → вставьте весь файл `supabase/update-2.sql` → Run. Затем так же `supabase/update-3.sql` (архив) и `supabase/update-4.sql` (время по подзадачам). Повторный запуск безопасен.
2. Edge Functions → tracker-api → Code → замените весь код содержимым `supabase/functions/tracker-api/index.ts` → Deploy.
3. Обновите файлы сайта (на GitHub это делается автоматически, если файлы загружал Claude).

## Как пользоваться

- **Мои задачи** — план на сегодня, неделю или месяц. Под сводкой есть поле для быстрого добавления задачи.
- **Доска** — колонки можно переключать: по статусам, по отделам или по категориям. Задачи перетаскиваются мышкой (на телефоне — долгим нажатием). Перетащили в другой отдел или категорию — у задачи поменялось это поле.
- **Перестановка колонок** — перетащите колонку за заголовок влево или вправо. Колонки статусов и категорий общие, их переставляют руководитель и администратор. Свои отделы каждый переставляет для себя.
- **Масштаб доски** — «Обычно», «Компактно» или «Всё на экране» (колонки сужаются, чтобы поместиться без прокрутки). Выбор запоминается на устройстве.
- **Отделы и категории** — у каждой задачи есть отдел и категория. Категории уже заданы: адаптация, каналы коммуникации, операционная работа, коммуникация с сотрудниками, активности, тимбилдинг, корпоратив, дни рождения, годовщины, опросы, отчётность, другие задачи. Отделы добавляются в разделе «Команда» или кнопкой «Новый отдел» на доске. Добавлять, переименовывать и удалять их могут руководитель и администратор.
- Когда задача попадает в «Готово», трекер спрашивает, сколько примерно она заняла: 15 мин, 30 мин, 1 ч, 2 ч, полдня или день. Вопрос можно пропустить.
- Время складывается: в карточке задачи кнопка «Добавить время» прибавляет к уже записанному. У каждой подзадачи своё время (спрашивается при выполнении подзадачи, добавить можно кнопкой «+ время» в любой момент), и оно автоматически суммируется в общее время задачи. Ошиблись — «исправить итог».
- **Командные** — задачи всем: у каждого своя копия, а руководитель видит «выполнили 3 из 5».
- **Архив** — выполненные задачи сами уходят с доски через 7 дней после выполнения. Раньше можно отправить кнопкой с коробкой в колонке «Готово» или в карточке задачи. В разделе «Архив» есть поиск и кнопка «Вернуть в работу». В итогах и целях архивные задачи учитываются.
- **Цели** — прогресс считается сам по привязанным задачам.
- **Итоги** — неделя, месяц, квартал или свой период: кто что сделал, сколько времени ушло, разбивка по отделам и категориям (удобно для квартальных отчётов). Часы за период — сумма времени по задачам, запланированным на этот период, включая незавершённые и время подзадач. Руководитель выбирает сотрудника в списке «Сотрудник» и видит его часы и таблицу задач со временем. Можно скачать CSV и открыть в Excel.
- **Таймер концентрации** — кнопка с часами в шапке. Фокус на 10, 15, 20, 30 или 50 минут, затем перерыв 5–15 минут. Таймер можно привязать к задаче, а по окончании одним нажатием добавить эти минуты к её времени. Он не сбрасывается, если переключить вкладку или перезагрузить страницу. В карточке своей задачи есть кнопка «Фокус».
- **Хай-файвы** — в выполненной задаче коллеги нажмите «🙌 Дать пять». Ему придёт уведомление, на карточке появится счётчик.
- **Напоминания** — в невыполненной задаче коллеги нажмите «👋 Напомнить» и выберите готовую фразу или напишите свою. Об одной задаче можно напоминать не чаще раза в 3 часа. Руководитель может напомнить сразу всем, кто не сделал задачу, назначенную нескольким людям (раздел «Командные»).
- Клавиша **N** открывает создание новой задачи.

## Безопасность

- Кто видит что, проверяет сама база (Row Level Security), а не только интерфейс. Участник физически не может получить личные задачи коллег, даже через запрос в обход сайта.
- В базе хранятся только хэши ссылок, сами ссылки восстановить нельзя: потерянную нужно выпустить заново.
- Одной ссылки недостаточно: без пароля войти нельзя. Пароль хранит Supabase в зашифрованном виде, администратор его не видит.
- Частые неверные попытки ввода пароля Supabase временно блокирует.
- После отзыва доступа данные скрываются сразу, а техническая сессия на устройстве истекает в течение часа.

## Если что-то не работает

- **«Серверная функция недоступна»** — проверьте, что функция называется `tracker-api` и развёрнута (шаг 3).
- **«Неверный пароль»** при правильном пароле — проверьте раскладку и Caps Lock. Если не помогает, администратор выпускает новую ссылку.
- **«Email logins are disabled»** — в Supabase откройте Authentication → Sign In / Providers и включите Email (подтверждение почты можно выключить: почта в трекере не используется).
- **«Неверный код установки»** — код в форме должен совпадать с `SETUP_SECRET`. После добавления секрета подождите минуту.
- **Ссылка не пускает, ошибка 401** — выключите проверку JWT у функции (шаг 3, пункт 4).
- **Пустая страница с текстом «Почти готово»** — не заполнен `config.js`.
- **Не обновляется у коллег без перезагрузки** — в Supabase откройте **Database** → **Publications** → `supabase_realtime` и убедитесь, что таблицы `tasks`, `columns`, `notifications` включены.
